# 모션 쇼릴 (60fps, 아홉 장면)

## 참고 영상
인스타그램 제작자 계정 grafigator, 게시물 ID DdwCXaQIHNU. 1920x1080, 60fps, 900프레임(15초), 음악만 있음.
부팅, 카운트다운, 글자 모션, 점 격자, 입자 공, 유리 구슬, 대시보드, 몽타주, 로고로 이어지는 가상의 모션 디자이너 쇼릴. 코드(three.js 계열)로 만든 영상이다.

## 실제 지시와 피드백
| 판 | 한 일 | 받은 말 |
|---|---|---|
| 시작 | 링크를 건네며 | "이것까지 추가로 학습해" / "두번째 분석한 영상도 똑 같이 만들어봐." |
| v1 | 렌더 틀을 만들고 작업자 5명이 장면을 나눠 측정 재현. 전체 평균 차이 5.5, 유리 구슬 장면만 18.3 | "와.. 이거 잘만들었다 depth 이게 좀 걸리긴 하다만.. 근사치를 정말 최소화 시키는 방법이 없나?" |
| 자동 맞추기 | 유리 구슬 18.3에서 13.5, 입자 5.3에서 3.4로 | "너무 오래 걸려~" / "토큰 소모가 너무 심한것 같아." |
| v2 | 측정·최적화를 다른 에이전트에 맡겨 마무리. 전체 4.15, 유리 구슬 12.65 | "워커에게 depth 이 부분만 좀 더 분석해서 만들라고 해봐." |
| v3 | 유리 구슬만 따로 분석 | "오차를 5이하로 만들어." -> 4.89 |

곁가지로 얻은 교훈: 같은 방식으로 홍보 영상을 새로 만들라고 측정용 에이전트에 통째로 맡겼더니 "제대로 안 만들었어. 너무 형편 없어.. 이거 코덱스가 만든거야?"를 들었다. 측정과 최적화는 맡기고, 화면을 결정하는 창작은 직접 한다.

## 측정 숫자
| 항목 | 값 |
|---|---|
| 장면별 오차 (v2, 0~255) | 0.37 / 1.03 / 2.10 / 4.03 / 3.33 / 12.65 / 3.83 / 3.42 / 2.94, 전체 4.15 |
| 유리 구슬 (v3) | 평균 4.89, 최대 14.0 (프레임 597) |
| 입자 개수 | 3,200 (화면에 작게 적힌 라벨 「3,200 PARTICLES」) |
| 입자 배치 | 피보나치 구. 원본 점 위치와의 챔퍼 거리 1.89px (다른 배치 공식은 4.9~5.3px) |
| 입자 공 | 초점 거리 1000px, 회전 ry -0.025rad/프레임, 입자별 지연 표 측정 |
| 격자 | 120px 격자, 일곱 색 순서 (i+4j+3+5k) mod 7 |
| 글자 모션 | 세로 8겹 복사 블러, 외곽선 잔상 3겹, O 고리 반지름 171.8 + 17.4 x 1.293^(f-215) 로 줌 |
| 유리 구슬 원인 분석 | 오차의 69%가 구슬 안쪽. 셰이딩 후보 6개를 같은 프레임에서 비교해 반사 환경이 최저(13.1), 굴절 후보는 22대. 환경이 프레임마다 -0.55도 회전. 반사 방향으로 샘플하는 128x64 환경 필드를 제어점 10개로 역적합 |

## 작업 순서
1. 60fps 900프레임을 전부 뽑고 장면 경계를 잰다(아홉 장면).
2. 화면에 적힌 라벨(「SDF RAYMARCHING」, 「3,200 PARTICLES」)을 구현 단서로 읽는다.
3. 장면마다 모듈 하나로 만든다. 모든 장면은 프레임 번호만으로 그린다(랜덤, 시계 금지).
4. 장면별 오차를 숫자로 낸다. 높은 장면 하나를 골라 집중한다.
5. 손으로 만지는 대신, 오차 숫자를 함수로 두고 값을 자동 탐색한다. 손으로 맞추면 덧칠이 생긴다.
6. 비교 점수가 이상하게 틀어지면 이미지 파일 색 변환 정보(PNG 감마)부터 의심한다. 이 문제를 찾아 제거했다.

## 새 영상에 시킬 때 쓰는 지시문 예
```
이 영상의 장면별 평균 차이를 0~255 숫자로 먼저 보여 줘.
제일 높은 장면 하나를 골라, 오차를 원인별로 나눠서 (구슬 안쪽, 가장자리 등) 어디서 나는지 말해 줘.
화면에 적힌 글자가 구현 방식의 단서일 수 있어. 숫자로 확인해서 공식을 정해.
손으로 덧칠하지 말고, 오차 함수를 만들어 자동으로 값을 찾아 줘. 목표는 5 이하야.
```
